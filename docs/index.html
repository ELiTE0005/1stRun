1stRun Runs Your Quickstart Like a Brand-New User




You give it
    

  • A public docs URL, like docs.getdbt.com/guides/duckdb
    • 

  • A tool name. Your coding agent finds its quickstart page.
    • 

  • A GitHub repo, for Doc-audit


It plans, runs and proves
    

  • One model call turns the page into at most 10 steps, one command each.
    • 

  • Each step runs in a clean Docker container.
    • 

  • A broken step gets a fix. A fresh container reruns every step with no model calls.


Not yet
    

  • Pages behind a login
    • 

  • API specs and bug reports as input
    • 

  • Long-running servers. It skips them and says why, like dbt docs serve below.




Every step runs on your machine. Only the docs page and the output of a failed step go to the model. Read the known limits

      Built With Alan AI, Claude, Docker and Langfuse
      

        

      • Alan AIThe AI agent inside 1stRun. It works through the quickstart steps and helps repair the ones that break.
        • 

      • ClaudePlans the runbook, repairs the first broken step and sorts each failure. It runs through the Claude Agent SDK.
        • 

      • DockerEvery run gets one clean container, and the proof run gets a second one.
        • 

      • LangfuseOptional. Every run becomes one trace, so a failed step comes with its cause.
        • 

      • OllamaOptional. A local model that backs up Claude when it sorts failures and judges audits.
        • 

      • FirecrawlOptional. Turns a docs page into clean markdown. Plain HTTP is the fallback.
        • 

      • git and GitHubDoc-audit reads the repo history. The fix goes out as a pull request you approve.
        •
